# LinScreen: руководство разработчика (Архитектура X11)

Документ предназначен разработчикам и ИИ-агентам, работающим с проектом LinScreen.
Он описывает устройство проекта, архитектурные решения, действующие соглашения
и правила поддержания стабильности эталонной кодовой базы под **X11**.

Основной язык проекта — русский: комментарии, сообщения интерфейса,
описания коммитов. Английский подключается словарём, см. раздел «Локализация».

---

## 1. Архитектурная концепция и ориентир на X11

LinScreen спроектирован как высокопроизводительный, легковесный комбайн
для работы в сессиях **X11** (Cinnamon, XFCE, MATE, KDE X11, GNOME X11 и др.).

### Почему отброшена универсальная мультиплатформенность:
1. **Изоляция и ограничения Wayland.** В Wayland приложениям запрещено знать
   координаты указателя мыши вне собственных окон, запрещено позиционировать
   всплывающие окна и контекстные меню абсолютными координатами, а также
   отсутствует доступ к дереву окон (`_NET_CLIENT_LIST`).
2. **Фрагментация порталов.** Порталы `xdg-desktop-portal` ведут себя по-разному
   в зависимости от композитора (отсутствие ScreenCast в Cinnamon XApp, отсутствие
   системного трея в базовом GNOME, различные требования к версиям FFmpeg).
3. **Чистота кода.** Попытки усидеть на двух стульях приводят к разрастанию
   слоёв абстракций, костылей и ухудшению пользовательского опыта.

**Принятое решение:**
Кодовая база LinScreen остаётся чистым, бескомпромиссным эталоном для **X11**.
Для Wayland и других графических серверов в будущем создаются **отдельные
независимые проекты**, использующие архитектурные принципы LinScreen, но
написанные под нативные API конкретных систем.

## 2. Запуск и проверки

```bash
.venv/bin/python main.py                 # запуск из исходных текстов
.venv/bin/python main.py --check         # проверка составных частей
.venv/bin/python -m unittest discover -s tests -t . # запуск всех тестов
.venv/bin/python -m flake8 .             # проверка стиля (PEP8)
.venv/bin/python -m mypy .               # проверка статической типизации
./build.sh                               # сборка переносимого AppImage
```

Окружение находится в `.venv`. Все проверки обязаны проходить без замечаний:
* Длина строки: 100 символов (flake8).
* Аннотации типов обязательны (`disallow_untyped_defs`).
* Все тесты (включая проверку полноты переводов) должны возвращать статус `OK`.

Режим `--check` выводит найденный FFmpeg, доступные видеокодеки, звуковые источники,
наличие модулей и состояние системного лотка.

## 3. Жёсткие правила разработки (CRITICAL CONSTRAINTS)

1. **Интерфейс никогда не блокируется.** Любые обращения к внешним процессам
   (FFmpeg), файловой системе или опросу звуковых устройств выполняются через
   `QProcess` или воркеры в пуле потоков (`core.workers.run_async()`). В главном
   GUI-потоке блокирующие вызовы запрещены.
2. **Аргументы командной строки собираются списками.** Никакой сборки команд через
   склейку строк. Пути с пробелами, кавычками и спецсимволами передаются как
   отдельные элементы списка `list[str]`.
3. **Кодирование — только внешним FFmpeg.** За всю работу со сжатием, масштабированием,
   палитрами для GIF и видеокодеками отвечает строго бинарник FFmpeg.
4. **Корректная остановка FFmpeg через "q".** Процесс записи останавливается
   передачей символа «q» в его стандартный ввод (`stdin`), чтобы медиаконтейнеры
   (MKV, MP4) успели финализировать заголовки. Принудительный `kill -9` допустим
   только как аварийный таймаут.
5. **Обезличенные комментарии.** Запрещены местоимения «я», «мы», «ты», «автор».
   Комментируются архитектурные развилки, неочевидные решения и физические причины,
   а не очевидный синтаксис языка.
6. **Обязательная локализация.** Любая пользовательская строка оборачивается в `tr()`
   и заносится в словарь `locale/en.json`. Тест `test_i18n.py` строго проверяет
   отсутствие как непереведённых, так и лишних (неиспользуемых) строк.

## 4. Карта модулей (Архитектура X11)

```
LinScreen/
├── app.py              # Контроллер приложения: связывает трей, горячие клавиши,
│                       # захват экрана, запуск FFmpeg и окна редактора.
├── main.py             # Точка входа: инициализация QApplication, проверка сессии X11,
│                       # блокировка единственного экземпляра, флаг --check.
├── core/
│   ├── session.py      # Проверка типа сессии (строго X11) и системных утилит.
│   ├── config.py       # Менеджер конфигурации INI: пути, форматы, хоткеи.
│   ├── hotkeys.py      # Глобальные горячие клавиши через pynput и python-xlib.
│   ├── autostart.py    # Управление автозапуском через XDG Autostart (.desktop).
│   ├── runtime.py      # Разрешение путей при работе из исходников и AppImage.
│   ├── workers.py      # Асинхронные задачи в пуле потоков без заморозки GUI.
│   └── i18n.py         # Подсистема интернационализации (ru/en).
├── capture/
│   ├── screen.py       # Захват экрана через QScreen и генерация входа x11grab.
│   ├── windows.py      # Анализ дерева окон X11 (python-xlib): Z-order, фильтрация
│   │                   # свёрнутых/служебных окон и подсветка элементов под курсором.
│   └── audio.py        # Обнаружение устройств PulseAudio/PipeWire через pactl.
├── encoder/
│   ├── ffmpeg.py       # Поиск бинарника FFmpeg, опрос кодеков и фильтров.
│   ├── process.py      # Управление подпроцессом FFmpeg (пауза, стоп, склейка).
│   ├── profiles.py     # Конфигурации форматов (MP4, MKV, GIF, WebM, ProRes).
│   └── images.py       # Сохранение растровых снимков (PNG, JPEG, WebP, AVIF).
├── editor/
│   ├── window.py       # Главное окно графического редактора аннотаций.

│   ├── items.py        # Графические примитивы (стрелки, рамки, текст, размытие, кроп).
│   └── icons.py        # Векторный генератор пиктограмм для панели инструментов.
└── ui/
    ├── tray.py         # Меню системного лотка и индикация состояния.
    ├── overlay.py      # Полноэкранный оверлей X11 с подсветкой объектов.
    ├── region_frame.py # Безрамочное окно-рамка вокруг записываемой области.
    ├── recorder_bar.py # Плавающая панель управления записью (таймер, пауза, стоп).
    ├── settings.py     # Диалоговое окно параметров программы.
    └── log_window.py   # Окно просмотра журнала внешних процессов.
```

## 5. Особенности реализации X11-контура

### Захват экрана и оконное дерево (`capture/windows.py`)
* Перед выводом оверлея программа делает моментальный снимок экрана через `QScreen.grabWindow(0)`
  и одновременно строит карту окон через вызов `XQueryTree` (библиотека `python-xlib`).
* Для каждого окна анализируются свойства `_NET_WM_STATE` (игнорируются свёрнутые окна
  `_NET_WM_STATE_HIDDEN`) и тип окна `_NET_WM_WINDOW_TYPE` (отсекаются всплывающие подсказки
  и служебные слои).
* Выполняется топологическая сортировка окон по Z-order: если верхнее окно перекрывает
  нижнее, поиск объекта под курсором отдаёт приоритет видимому окну переднего плана.

### Видеозапись (`capture/screen.py` и `encoder/`)
* Захват видеопотока осуществляется напрямую демультиплексором FFmpeg `-f x11grab`.
* Вход формируется с точными координатами области: `-i :0.0+X,Y` с частотой кадров `fps`
  и флагом отрисовки указателя мыши `-draw_mouse 1`.
* Во время паузы FFmpeg процесс мягко завершает текущий сегмент, а при возобновлении
  начинается запись нового файла. По окончании записи все сегменты объединяются
  через `concat demuxer` без повторного перекодирования.

### Горячие клавиши (`core/hotkeys.py`)
* Перехват глобальных комбинаций клавиш ведётся библиотекой `pynput` в отдельном
  демоне, использующем низкоуровневые вызовы X11 `XGrabKey`.
* Для стабильной работы с различными раскладками клавиатуры (RU/EN) выполняется
  сопоставление скан-кодов и уровней модификаторов (Shift).

## 6. Сборка AppImage (`build.sh`)

Сборщик упаковывает проект в автономный переносимый файл:
1. Создаётся чистое изолированное виртуальное окружение Python.
2. Устанавливаются зависимости из `requirements.txt`.
3. В пакет внедряется оптимизированный статический бинарник FFmpeg.
4. Добавляются необходимые системные библиотеки X11 (`libxcb-cursor0` и др.).
5. Утилита `appimagetool` упаковывает каталог `AppDir` в исполняемый образ
   `dist/LinScreen-x86_64.AppImage`.

## 7. Ориентиры для создания дочерних проектов

При создании отдельных версий LinScreen для других платформ (Wayland, macOS, Windows)
рекомендуется использовать текущий проект как архитектурный шаблон:
* Сохранить модульное разделение: `core/`, `capture/`, `encoder/`, `editor/`, `ui/`.
* Модули `editor/` (холст аннотаций, векторные иконки), `encoder/` (профили FFmpeg,
  контроллер процессов) и `core/config.py` переносятся без изменений.
* В новом проекте подлежат полной замене только платформозависимые модули захвата:
  `capture/screen.py`, `capture/windows.py`, `core/hotkeys.py` и оверлеи `ui/`.
