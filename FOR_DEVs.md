# LinScreen: описание для разработчика Wayland-части

Документ предназначен агенту, который будет доводить поддержку Wayland.
Он описывает устройство проекта, действующие соглашения, текущее состояние
Wayland-ветки, перечень мест, которые придётся затронуть, и подводные
камни, уже найденные опытным путём.

Основной текст проекта — русский: комментарии, сообщения интерфейса,
описания коммитов. Английский подключается словарём, см. раздел
«Локализация».

---

## 1. Что это за программа

Приложение в системном трее для снимков экрана, записи видео и разметки
снимков. Собственных кодеков нет: захват и кодирование выполняет внешний
FFmpeg, звук берётся у PulseAudio или PipeWire через утилиту `pactl`,
снимки в Wayland получает портал рабочего стола.

Сейчас **полностью работает только сессия X11**. В Wayland доступны
снимки экрана через портал; запись экрана и глобальные клавиши — нет.

## 2. Запуск и проверки

```bash
.venv/bin/python main.py                 # запуск из исходных текстов
.venv/bin/python main.py --check         # проверка составных частей
.venv/bin/python -m unittest discover -s tests -t .
.venv/bin/python -m flake8 .
.venv/bin/python -m mypy .
./build.sh                               # сборка образа AppImage
```

Окружение уже создано в `.venv`. Все три проверки обязаны проходить без
замечаний: длина строки 100 символов, аннотации типов обязательны
(`disallow_untyped_defs`).

Режим `--check` выводит найденный FFmpeg, доступные кодеки и фильтры,
звуковые источники, наличие модулей и состояние оконной подсистемы. Это
первое, что стоит запускать при разборе неполадок.

## 3. Жёсткие правила

Нарушение любого из них считается ошибкой, а не стилевым разногласием.

1. **Интерфейс не блокируется.** Любое обращение к внешнему процессу,
   порталу или файловой системе идёт через `QProcess`, `core.workers.run_async()`
   либо сигналы D-Bus. Синхронных вызовов в обработчиках событий быть не должно.
   Исключения помечены в коде явно (например, запись файла журнала в
   несколько десятков байт).
2. **Аргументы командной строки собираются списками.** Строка команды
   нигде не склеивается: пробелы, кавычки и национальные символы в путях
   должны работать без экранирования. `shlex.join` применяется только для
   вывода в журнал.
3. **Кодирование — только внешним FFmpeg.** Собственных преобразований
   кадров, палитр и контейнеров не пишется.
4. **Остановка записи — передачей символа «q» в stdin.** Флаг `-nostdin`
   добавлять нельзя. Эскалация до `SIGTERM` и `SIGKILL` выполняется только
   по истечении срока ожидания, см. `encoder/process.py:request_graceful_stop`.
5. **Комментарии обезличены.** Запрещены «я», «мы», «ты», «автор».
   Комментируются решения и причины, а не очевидные действия.
6. **Каждая новая пользовательская строка оборачивается `tr()`** и
   добавляется в `locale/en.json`, иначе падают тесты. См. раздел 10.

## 5. Контракты, которые нужно соблюсти

Новый бэкенд захвата обязан выдавать те же структуры, что и X11-путь, —
тогда весь слой кодирования, паузы и склейки заработает без изменений.

```python
# encoder/profiles.py
@dataclass(frozen=True)
class VideoInput:
    args: Sequence[str]          # готовые аргументы входа FFmpeg целиком
    fps: int = 30
    width: int | None = None
    height: int | None = None
    needs_even_padding: bool = True   # дополнение до чётных сторон фильтром

# capture/portal.py
@dataclass(frozen=True)
class PipeWireStream:
    file_descriptor: int   # уже продублирован через os.dup, наследуется потомком
    node_id: int
    width: int = 0
    height: int = 0

# encoder/process.py
@dataclass
class RecordingJob:
    output_path: Path
    make_step: Callable[[Path], FFmpegStep]   # команда для очередного фрагмента
    ffmpeg_path: str = "ffmpeg"
    segment_suffix: str = ".mkv"
    segment_muxer: str = "matroska"
    post_process: Callable[[Path, Path], list[FFmpegStep]] | None = None
    work_dir: Path | None = None
```

`make_step` вызывается **на каждый фрагмент записи**: при паузе запись
разбивается на части, которые затем склеиваются демультиплексором
`concat` без перекодирования. Поэтому источник захвата должен допускать
повторное открытие. Для потока PipeWire это означает, что дескриптор
должен оставаться пригодным после завершения первого процесса FFmpeg,
либо сеанс портала нужно открывать заново — **это не проверено, см. 8.1**.

## 7. Текущее состояние Wayland

### Работает

**Снимки экрана через портал.** `capture/portal.py:ScreenshotPortal`
реализован и проверен на живой системе: вызов `org.freedesktop.portal.Screenshot`,
ожидание сигнала `Response`, чтение файла по возвращённому URI и его
удаление. Проверено на портале версии 2 с бэкендом GTK.

### Реализовано, но не проверено

**`capture/portal.py:ScreenCastPortal`** — полная последовательность
`CreateSession` → `SelectSources` → `Start` → `OpenPipeWireRemote`.
Код написан по спецификации, но **ни разу не выполнялся на системе с
доступным интерфейсом ScreenCast**: на машине разработки установлены
бэкенды `xdg-desktop-portal-gtk` и `-xapp`, которые этот интерфейс не
предоставляют. Считать его рабочим нельзя.

**`capture/screen.py:build_pipewire_video_input`** — собирает вход вида
`-f lavfi -i pipewiregrab=fd=N:node=M`. Синтаксис взят из документации
фильтра и не проверялся на настоящем потоке.

### Не реализовано

* **Глобальные клавиши.** `core/hotkeys.py` умеет только `pynput`, то есть
  X11. Для Wayland нужен `org.freedesktop.portal.GlobalShortcuts`.
* **Выделение области.** `ui/overlay.py` полагается на то, что окно можно
  разместить по заданным координатам поверх всех прочих
  (`X11BypassWindowManagerHint`). В Wayland приложение своей позицией не
  управляет.
* **Геометрия активного окна.** `capture/screen.py:active_window_rect`
  использует свойство `_NET_ACTIVE_WINDOW` протокола X11.

### Почему не проверено: три независимых препятствия

1. **Бэкенд портала без ScreenCast.** Требуется `xdg-desktop-portal-gnome`,
   `-kde`, `-wlr` или `-hyprland`. Проверить наличие:
   ```bash
   busctl --user get-property org.freedesktop.portal.Desktop \
       /org/freedesktop/portal/desktop org.freedesktop.portal.ScreenCast version
   ```
2. **FFmpeg без фильтра `pipewiregrab`.** Фильтр появился в FFmpeg 7.1, но
   собирается только при наличии libpipewire во время сборки. **Вложенная
   в образ сборка FFmpeg 8.1 от BtbN его не содержит** — проверено:
   ```bash
   vendor/ffmpeg -hide_banner -filters | grep pipewiregrab   # пусто
   ```
   Системный FFmpeg 6.1.1 из дистрибутива — тем более.
3. **Сессия Wayland.** Разработка велась в X11 (Cinnamon).

## 8. Что предстоит сделать

Задачи упорядочены: каждая следующая опирается на предыдущую.

### 8.1. Захват видеопотока

Сначала проверить уже написанное: запустить приложение в Wayland с
подходящим бэкендом портала, вызвать запись и посмотреть в журнал
(«Журнал…» в меню трея либо `~/.cache/linscreen/linscreen.log`).
Ожидаемые точки отказа: разбор структуры `a(ua{sv})` в
`ScreenCastPortal._first_stream`, получение дескриптора из
`OpenPipeWireRemote`, синтаксис фильтра.

Дальше выбрать способ доставки кадров в FFmpeg:

* **`pipewiregrab`** — самый прямой путь, но требует сборки FFmpeg с
  libpipewire. Потребуется заменить вложенную сборку: либо собирать
  FFmpeg самостоятельно, либо найти готовую с этим фильтром. Обязательно
  дополнить `--check` проверкой и внятным сообщением.
* **GStreamer через `pipewiresrc`** — поток передаётся в FFmpeg по каналу
  (`-f rawvideo -i pipe:` либо контейнером matroska). Не требует
  особой сборки FFmpeg, но добавляет зависимость от GStreamer и второй
  процесс в цепочке. Контроль остановки усложняется: «q» нужно передавать
  FFmpeg, а GStreamer завершать отдельно.
* **Готовые программы записи** (`wf-recorder`, `gpu-screen-recorder`) —
  противоречит правилу «кодирование только FFmpeg» и лишает приложения
  профилей кодирования. Как запасной путь допустимо, но не как основной.

Рекомендуется первый вариант: он сохраняет всю существующую цепочку
профилей, паузы и склейки без изменений.

**Обязательно проверить паузу.** При паузе процесс FFmpeg завершается и
запускается заново для следующего фрагмента. Нужно выяснить, переживает
ли это дескриптор PipeWire. Если нет — придётся либо открывать поток
заново на каждый фрагмент (и тогда портал может переспрашивать
разрешение), либо запретить паузу в Wayland с внятным сообщением.

**Дескриптор и дочерний процесс.** Дескриптор уже дублируется через
`os.dup` в `ScreenCastPortal._on_started`: `dup` не переносит признак
закрытия при запуске процесса, поэтому копия должна достаться FFmpeg по
наследству. Это предположение требует проверки.

Если `QProcess` дескриптор не передаёт, штатного способа поправить дело
нет: метод `setChildProcessModifier` в PySide6 не предоставляется
(проверено на версии 6.11). Запасные пути:

* запускать FFmpeg через `subprocess.Popen` с `pass_fds=(fd,)`, а чтение
  потоков и передачу «q» вести самостоятельно. Это потребует отдельной
  ветки в `encoder/process.py`, причём остальная логика фрагментов,
  склейки и остановки должна остаться общей;
* передавать поток через посредника (GStreamer), тогда дескриптор нужен
  только ему, а FFmpeg читает обычный канал.

Прежде чем переписывать контроллер процессов, стоит проверить простым
опытом: получить дескриптор, запустить через `QProcess` команду
`sh -c 'ls -l /proc/self/fd'` и посмотреть, виден ли он потомку.

### 8.2. Выделение области

В Wayland приложение не может разместить окно поверх экрана по
координатам, поэтому нынешний оверлей непригоден. Варианты:

* положиться на диалог портала: `SelectSources` позволяет выбрать монитор
  или окно, но не произвольный прямоугольник;
* выделять область **внутри уже полученного потока** — портал отдаёт
  весь монитор, а обрезка выполняется фильтром `crop` в FFmpeg. Тогда
  оверлей показывается поверх снимка, полученного порталом Screenshot,
  и служит только для выбора координат;
* внешняя утилита `slurp` для композиторов wlroots, уже учтённая в
  `core/session.py:region_backend`.

Второй вариант предпочтителен: он работает в любом композиторе и
сохраняет привычное поведение.

### 8.3. Активное окно

Портал `Screenshot` не умеет снимать конкретное окно. Разумное решение —
скрыть пункт «Активное окно» в Wayland либо свести его к выбору окна в
диалоге портала через `SelectSources` с типом `WINDOW`.

### 8.4. Глобальные клавиши

Интерфейс `org.freedesktop.portal.GlobalShortcuts` (версия 1):
`CreateSession`, `BindShortcuts`, сигналы `Activated` и `Deactivated`.
Шаблон запроса уже реализован классом `PortalRequest` — использовать его,
а не писать обмен заново.

Встроить в `core/hotkeys.py` вторым бэкендом: `HotkeyManager.apply()` уже
разделяет случаи по `session.supports_native_hotkeys`, туда и добавляется
ветка. Сигнал `activated` наружу остаётся прежним, приложение ничего не
заметит.

Учесть: портал показывает пользователю диалог подтверждения и может
изменить назначенные сочетания. Настройки клавиш в этом случае носят
рекомендательный характер, о чём стоит сказать в окне настроек.

### 8.5. Прочее

* `app.py:_hide_windows` скрывает собственные окна во время записи —
  проверить, что в Wayland это происходит до первого кадра.
* Панель записи `ui/recorder_bar.py` позиционируется по координатам
  экрана; в Wayland её положение определяет композитор.
* `capture/screen.py:grab_with_grim` — запасной путь для wlroots, уже есть.

## 9. Как проверять

На машине без Wayland проверить можно немногое. Минимум, что стоит
сделать до переноса на живую сессию:

1. `--check` показывает `Захват PipeWire (Wayland)` — значение берётся из
   `FFmpegCapabilities.can_capture_pipewire`.
2. Модульные проверки разбора и сборки команд: `tests/test_profiles.py`
   строит команды без обращения к системе, туда же добавляются проверки
   входа PipeWire.
3. Наличие интерфейсов портала: функции `is_screenshot_available()` и
   `is_screencast_available()` в `capture/portal.py`.

На живой сессии Wayland последовательность разбора неполадок:

```bash
# какие интерфейсы даёт установленный бэкенд портала
busctl --user introspect org.freedesktop.portal.Desktop /org/freedesktop/portal/desktop | grep portal
# журнал портала
journalctl --user -b -u xdg-desktop-portal --since "5 min ago"
# журнал приложения
tail -f ~/.cache/linscreen/linscreen.log
```

## 10. Локализация: обязательное правило

Исходный язык — русский, строки записаны прямо в коде и оборачиваются
`tr()` из `core/i18n.py`. Переводы лежат в `locale/en.json`, ключом
служит исходная строка.

**Любая новая пользовательская строка обязана быть добавлена в словарь**,
иначе `tests/test_i18n.py` не пройдёт: проверяется полнота словаря,
отсутствие лишних записей, совпадение подстановок `{0}`, `{1}` и
отсутствие кириллицы в английских значениях.

Строки, объявленные на уровне модуля (названия профилей, примечания к
файлу настроек), переводятся **в месте показа**, а не при объявлении:
на момент загрузки модуля язык ещё не выбран.

## 11. Подводные камни, найденные опытным путём

Каждый из них стоил времени; повторно на них наступать не нужно.

| Тема | Суть |
|---|---|
| Разбор синтаксического дерева | `ast` возвращает смещения **в байтах**, а не в символах: на строках с кириллицей правка текста по ним разъезжается |
| `pactl` | в режиме `-f json` не выводит не-ASCII строки и подставляет `"(null)"`; основной путь — подробный текстовый вывод с `LC_ALL=C` |
| Список фильтров FFmpeg | в версии 8 столбец признаков сократился с трёх символов до двух, разбор должен принимать оба вида |
| Склейка `concat` | без `-map 0` сохраняется только по одному потоку каждого типа: вторая звуковая дорожка теряется |
| Выход по «q» | часть сборок FFmpeg возвращает код 255; он считается успешным наравне с нулём |
| `QProcess` и таймеры | таймер эскалации нужно создавать потомком процесса: иначе он срабатывает после удаления объекта и роняет обработчик |
| `PySide6` | `QObject.disconnect()` без аргументов не поддерживается; применяется `blockSignals(True)` перед удалением |
| Ошибка в обработчике | не прекращает работу приложения: `sys.excepthook` вызывается, цикл событий продолжается. Окно об ошибке показывается только один раз за запуск |
| PyInstaller | подменяет `LD_LIBRARY_PATH`; системные утилиты, запущенные из собранного приложения, ломаются. Восстановление — `core/runtime.child_environment()` |
| Клавиша PrintScreen | с нажатым Shift выдаёт символ `Sys_Req`, а не `Print`: для сочетаний с Shift регистрируются символы верхнего уровня, см. `core/hotkeys.shifted_keysyms` |
| Буквенные сочетания | работают при любой раскладке: перехватчик сам приводит клавишу к основной группе |
| Сохранение PNG в Qt | степень сжатия задаётся в процентах `setCompression(0…100)`, а не уровнем zlib |
| Оверлей выделения | изображение готовится один раз в размер окна; затемняются только полосы вокруг области, перерисовывается лишь изменившаяся часть |
| AppImage | образ монтируется, а не распаковывается: запуск за полсекунды вместо трёх. Вложения лежат в `usr/bin/_internal`, путь даёт `core.runtime.bundle_dir()` |
