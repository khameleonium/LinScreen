# LinScreen: руководство разработчика (общая программа X11 + Wayland)

Документ предназначен разработчикам и ИИ-агентам, работающим с LinScreen.
Он описывает устройство проекта, архитектурные решения, действующие
соглашения и известные особенности окружений.

Основной язык проекта — русский: комментарии, сообщения интерфейса,
описания коммитов. Английский подключается словарём `locale/en.json`.

Возможности, настройки, форматы и строки интерфейса в X11 и Wayland должны
совпадать; различается только набор модулей графической системы.

---

## 1. Архитектурная концепция

Одна программа для X11 и Wayland. Общее ядро не знает, какая графическая
система работает: всё платформенное скрыто за интерфейсом `Backend`
(`backends/base.py`):

| Действие | X11 (`backends/x11`) | Wayland (`backends/wayland`) |
|---|---|---|
| Снимок рабочего стола | `QScreen.grabWindow` | портал Screenshot (+ кадры ScreenCast без указателя) |
| Окно под указателем | дерево окон python-xlib | скрипт KWin (только KDE) |
| Оверлей выделения | одно окно на весь стол | окно на каждый монитор |
| Источник видео | FFmpeg x11grab | ScreenCast → PipeWire → GStreamer → FIFO |
| Рамка записи | окно X11 вне менеджера окон | KWin (KDE) либо процесс XWayland |
| Панель записи в углу | `move()` | KWin (KDE) |
| Глобальные клавиши | pynput | GlobalShortcuts / kglobalaccel |
| Буфер обмена | Qt | wl-copy |

Выбор набора — `backends/__init__.py`: по `XDG_SESSION_TYPE`, либо явно
ключом `--platform x11|wayland` / переменной `LINSCREEN_PLATFORM`. Модули
невыбранного набора не импортируются; платформа Qt (`xcb` / `wayland`)
задаётся в `main.py` под выбранный набор.

Правило: в общем ядре нет проверок «если X11 / если Wayland» — различие
выражается новым методом интерфейса `Backend`.

## 2. Запуск и проверки

```bash
.venv/bin/python main.py                 # запуск из исходных текстов
.venv/bin/python main.py --check         # проверка составных частей и порталов
.venv/bin/python main.py --screenshot    # действие для работающего экземпляра
.venv/bin/python -m unittest discover -s tests -t .
.venv/bin/python -m flake8 .
.venv/bin/python -m mypy .
./build.sh                               # сборка dist/LinScreen-x86_64.AppImage
```

Все проверки обязаны проходить без замечаний: длина строки 100 символов,
обязательные аннотации типов, полнота словаря переводов (`test_i18n.py` ловит и
непереведённые, и лишние строки).

### Живая проверка

Каталог `tools/` содержит инструменты для проверки на настоящем рабочем столе:

* `tools/emulate_input.py` — мышь и клавиатура через `/dev/uinput` (нужны
  `python3-evdev` и право записи в `/dev/uinput`), запускается системным `python3`;
* `tools/screenshot.sh файл.png` — снимок экрана средствами spectacle;
* `tools/restart_app.sh [stop]` — перезапуск приложения по номеру из файла блокировки.

Координаты `emulate_input.py` задаются в точках снимка экрана, их отображение на
логические координаты делает сам композитор.

**Никогда не эмулировать `Ctrl+Alt+F1…F12`** (в том числе с `Shift`): это
переключение виртуального терминала, сеанс уходит на пустой экран, что выглядит как
зависание. `emulate_input.py` такие сочетания отвергает и после работы проверяет,
что сеанс остался активным.

Для проверок без конфликтов с другими программами сочетания в
`~/.config/linscreen/config.ini` можно оставить пустыми, а действия вызывать
ключами командной строки.

## 3. Жёсткие правила разработки

1. **Интерфейс никогда не блокируется.** Обращения к порталам, KWin и kglobalaccel,
   запуск внешних процессов и файловые операции выполняются в пуле потоков
   (`core.workers.run_async()`) либо через `QProcess`. Функции `core/portal.py`,
   `backends/wayland/kwin.py`, `backends/wayland/screencast.py` блокирующие и вызываются только из
   фоновых потоков.
2. **Аргументы командной строки собираются списками.** Никакой склейки строк.
3. **Кодирование — только внешним FFmpeg.** GStreamer лишь принимает кадры из PipeWire.
4. **Остановка FFmpeg через «q».** Кадры подаются через именованный канал, а не через
   стандартный ввод, чтобы тот оставался свободным для команды остановки.
5. **Никакого X11.** Ни python-xlib, ни pynput, ни x11grab, ни обращений к XWayland.
6. **Обезличенные комментарии.** Запрещены местоимения «я», «мы», «ты», «автор».
7. **Обязательная локализация.** Любая строка интерфейса оборачивается в `tr()` и
   заносится в `locale/en.json`; `test_i18n.py` ловит и непереведённые, и лишние строки.

## 5. Особенности реализации

### Идентичность приложения (`core/identity.py`, `core/autostart.py`)
* Идентификатор `io.github.khameleonium.LinScreen` передаётся композитору
  (`QApplication.setDesktopFileName`) и регистрируется у портала
  (`org.freedesktop.host.portal.Registry`, xdg-desktop-portal 1.19+).
* Регистрация требует ярлыка `~/.local/share/applications/<id>.desktop`. Он создаётся
  при каждом запуске; если пользователь не просил ярлык в меню, он помечается
  `NoDisplay=true`.
* Каталоги настроек и журнала — `linscreen-wayland`, файл блокировки —
  `linscreen.lock`.

### Обмен с D-Bus (`core/portal.py`)
* Используется jeepney, а не QtDBus: привязки PySide6 не умеют передавать `uint32`,
  а порталы параметры неверного типа молча отбрасывают.
* `open_dbus_router` — генераторный контекстный менеджер; ссылка на него удерживается,
  иначе сборщик мусора закроет соединение.
* Подписка на ответ оформляется до вызова: путь объекта запроса вычисляется по
  метке `handle_token`.

### Снимки (`capture/screen.py`, `backends/wayland/overlay.py`)
* Портал сохраняет снимок в файл; файл читается и сразу удаляется.
* Масштаб вычисляется по фактическому размеру снимка, а не по коэффициенту Qt.
* Оверлей — по полноэкранному окну на каждый монитор с общим состоянием выделения
  в логических координатах рабочего стола.
* KDE Plasma встраивает указатель мыши в снимок портала; параметра, отключающего
  это, в интерфейсе портала нет.

### Запись (`backends/wayland/screencast.py`, `encoder/process.py`)
* Сеанс портала открывается на всю запись. Каждый фрагмент получает собственное
  соединение `OpenPipeWireRemote`: переиспользовать соединение после завершения
  процесса GStreamer нельзя.
* Метки восстановления (`restore_token`, `persist_mode=2`) хранятся по мониторам в
  `screencast-tokens.json`; при действующей метке диалог не показывается.
* Размер потока берётся из ответа портала. Коэффициент Qt при дробном масштабе
  неточен (1,25 округляется до 2). Конвейер сначала приводит кадр к этому размеру, а
  затем вырезает область, поэтому расхождение не ломает согласование форматов.
* Поставщик кадров (`FrameFeed`) запускается перед FFmpeg; дескриптор PipeWire
  наследуется и сразу закрывается в приложении. Если GStreamer завершился, не открыв
  канал, FFmpeg освобождается кратким открытием канала на запись.
* Фрагмент без закодированных кадров (только заголовок контейнера) в склейку не
  попадает.

### Снимки без указателя (`backends/wayland/snapshot.py`)
* Портал Screenshot в KDE встраивает указатель. Параллельно открывается сеанс ScreenCast
  со скрытым указателем на все мониторы (`multiple=true`, одно разрешение
  `screenshot|all-monitors`), с каждого потока берётся один кадр (`num-buffers=1`).
* Портал не сообщает, какой поток какому монитору соответствует: кадры сопоставляются
  с участками снимка портала по сходству уменьшенных копий. Сопоставление запоминается
  (`screenshot-streams.json`) вместе с конфигурацией мониторов, и дальше снимок
  собирается только из кадров — 0,2 с вместо 2,2 с у портала KDE с двумя мониторами.
* Области, лежащие на одном мониторе, вырезаются из его родного кадра без растяжения.
* Запись тоже открывает сеанс с этим разрешением и берёт поток нужного монитора:
  Plasma 5.27 хранит в разрешении положение монитора, и отдельные разрешения на каждый
  монитор путали экраны.

### Лупа (`ui/magnifier.py`)
* Общий модуль для обеих графических систем: получает снимок, положение указателя и границы
  монитора в логических координатах, масштаб берёт по размеру снимка.
* Радиус меняется колесом, запоминается в `[magnifier]` при закрытии оверлея.

### Меню трея (`ui/tray.py`)
* В Wayland меню значка рисует панель по описанию через D-Bus. Изменение структуры меню
  во время показа (раньше подменю мониторов пересобиралось в `aboutToShow`) опустошает
  открытое меню, поэтому подменю пересобирается только при смене состава экранов.

### Горячие клавиши (`backends/wayland/hotkeys.py`)
* Plasma 5.27 реализует раннюю редакцию GlobalShortcuts (действия ожидаются в
  `CreateSession`), а xdg-desktop-portal 1.18+ этот параметр отбрасывает. Пустой
  перечень действий в ответе на `BindShortcuts` признаётся отказом, и в KDE
  используется kglobalaccel.
* Компонент kglobalaccel называется идентификатором приложения **без** `.desktop`:
  для компонентов с таким суффиксом служба запускает действия ярлыка, а не отправляет
  сигнал.
* KWin 5.27 выбрасывает Shift из сочетаний с буквами (`Ctrl+Alt+Shift+J` приходит как
  `Ctrl+Alt+J`), а `Shift+Print` приходит как `SysReq`: регистрируются оба варианта.
* Поле ввода сочетания определяет буквы и цифры по скан-коду (латиница при любой
  раскладке, текст нажатия с Ctrl непригоден), а Shift — по физической клавише: при
  переключении раскладки сочетанием Ctrl+Shift нажатие Shift приходит как смена
  раскладки, и Qt в Wayland не сообщает Shift, израсходованный на заглавную букву.
* В KDE портал GlobalShortcuts не вызывается вовсе: xdg-desktop-portal-kde на каждый
  `BindShortcuts` открывает «Параметры системы». Сочетания сразу регистрируются в
  kglobalaccel.
* Источник истины — настройки приложения: при каждом запуске они применяются
  принудительно (`NoAutoloading`), иначе клавиша, однажды не назначенная из-за
  конфликта, осталась бы пустой навсегда. Изменения из «Параметров системы» служба
  сообщает сигналом `yourShortcutsChanged` (Plasma 5.27+, `a(ai)`) или
  `yourShortcutGotChanged` (`ai`); они переносятся в `config.ini`.
* Служба не отдаёт клавишу, занятую другим компонентом. Владелец определяется методом
  `action(key)`, пользователь получает сообщение с названием приложения.
* Компоненты с устаревшим идентификатором (`LEGACY_KGLOBALACCEL_COMPONENTS`) удаляются
  при каждой регистрации: они удерживали бы те же клавиши.
* Удаление: `unregister` каждого действия и `Component.cleanUp()` — иначе в
  «Параметрах системы» остаётся пустая запись. Полное удаление следов программы —
  `core/uninstall.py` (`--uninstall`, кнопка в настройках).

### Скрипты KWin (`backends/wayland/kwin.py`)
* Скрипт загружается через `org.kde.kwin.Scripting.loadScript`, запускается
  (`/Scripting/ScriptN` в Plasma 6, `/N` в Plasma 5) и выгружается.
* Результат скрипт передаёт вызовом `callDBus` метода `ReportWindows` службы
  приложения; ожидающий поток получает его по метке.
* Окна приложения находятся по началу заголовка: Qt дописывает к нему название
  приложения.

### Отрисовка окон
* Связка Qt 6.11 и KWin 5.27 искажает первые кадры окон, переданные через разделяемую
  память (строки изображения съезжают). По умолчанию включена отрисовка виджетов через
  OpenGL (`QT_WIDGETS_RHI=1`); значение `0` в окружении возвращает прежний способ.

## 6. Сборка AppImage (`build.sh`)

1. Создаётся виртуальное окружение, устанавливаются зависимости и PyInstaller.
2. Вкладывается статическая сборка FFmpeg (BtbN).
3. PyInstaller собирает каталог вместе с плагинами Qt для Wayland.
4. `appimagetool` упаковывает `dist/LinScreen-x86_64.AppImage`; ярлык и значок
   названы идентификатором приложения.

`tools/bundle_gstreamer.sh` вкладывает GStreamer (нужные модули) с клиентом PipeWire
и замыканием библиотек (~16 МБ). `backends/wayland/gstreamer.py` предпочитает системный комплект,
если в нём есть все элементы, и переходит на вложенный иначе.
`LINSCREEN_BUNDLED_GSTREAMER=1` принудительно включает вложенный — для проверки образа.

## 7. Проверено и не проверено

Проверено вживую на KDE Plasma 5.27.12 (Linux Mint 22.3), xdg-desktop-portal 1.20,
Qt 6.11, два монитора (1920×1080 при масштабе 1 и 1536×864 при 1,25): снимки области
(в том числе через границу мониторов), окна под курсором, отдельного монитора, всего
экрана, без указателя; лупа; запись всего экрана, монитора, области с рамкой, MKV со
звуком (две дорожки), пауза и продолжение, GIF; синхронизация звука — в среднем
−63 мс (звук раньше, разброс 1…100 мс), без дрейфа, сохраняется после паузы — сдвиг
близок к задержке вывода на USB-гарнитуру и одинаков для любого захвата через монитор
источника PulseAudio; меню трея, настройки, английский язык; горячие клавиши через
kglobalaccel; команды извне; буфер обмена; AppImage с системным и вложенным GStreamer.

Проверено вживую в GNOME 46 (Linux Mint 22.3, два монитора 1920×1080): окно
«Компоненты системы» (обнаружение, копирование команд, автоисправление), меню трея
через расширение AppIndicator, работа без трея через действия ярлыка, снимки области,
через границу мониторов, без указателя, лупа, запись области со звуком, пауза,
буфер обмена из образа. Не проверено: портал GlobalShortcuts (появился в GNOME 48),
дробный масштаб в GNOME.

### Особенности GNOME
* Портал снимков GNOME показывает окно подтверждения только приложению в фокусе
  (`Only the focused app is allowed to show a system access dialog`), поэтому нужна
  запись в хранилище разрешений (`screenshot`/`screenshot`, app_id → `yes`) —
  её предлагает окно «Компоненты системы».
* Расширение AppIndicator запрашивает меню значка при регистрации раньше, чем Qt
  публикует его на шине; значок регистрируется повторно через секунду (`ui/tray.py`).
* Кадры PipeWire в GNOME приходят с незаполненным каналом прозрачности: снимок
  переводится в RGB, иначе он блёклый.
* Мониторы одинакового размера: кадр сопоставляется только участку с теми же
  пропорциями, иначе кадр монитора мог «подойти» всему рабочему столу.
* Интерактивный режим портала снимков роняет xdg-desktop-portal-gnome 46 (SEGV);
  приложение им не пользуется.
